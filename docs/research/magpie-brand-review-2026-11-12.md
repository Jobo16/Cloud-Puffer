# Magpie 的命名与仓库呈现：对本项目的借鉴

状态：品牌方向研究。随后已确定以 Cloud Puffer 作为仓库主品牌；当前页面设计与已上线地址不变。

## Magpie 做对了什么

[Magpie 的英文 README](https://github.com/yetone/magpie)用一个简短、可记的名词作名字，用「Every agent's model. One place.」解释产品价值。紧接着用 Claude Code、Codex、Gemini CLI 搭配具体模型的例子说明用途，然后给出截图、适用人群、快速开始和整体结构。[中文 README](https://github.com/yetone/magpie/blob/main/README.zh-CN.md)沿用同一个名字与相同顺序。名字负责记忆点，副标题和例子负责解释功能。

Magpie 连接的是 Agent 与模型供应方；本项目连接的是用户的收发渠道与 Agent 运行位置。可以借鉴它的表达方式，不能沿用「任意 Agent、任意渠道」一类尚未实现的能力承诺。

## 本项目目前的品牌问题

- 「云上小肥鱼」把注意力放在一个拟人化助手上，「JOJOBOT」又像工程代号，两个名字都没有形成统一的产品识别。
- 仓库封面写「一点秩序，一点从容」，首页主标题写「一句话，把事记下」，都侧重待办和记忆；当前产品方向的核心是同一账号的跨渠道对话，以及云端或用户电脑上的 Agent 选择。
- 封面和网页使用真人风格头像，品牌名却是鱼；头像、名字与产品结构之间没有共同的图形语言。
- README 一开始就展示大封面和长篇状态说明。读者需要往下读，才能明白渠道、Agent、主对话分别承担什么。

## 命名标准

1. 一个简短、容易念和输入的主名；不在主名中堆叠 AI、Bot、Cloud、Gateway。
2. 名字可以是具象名词，不要求字面描述架构；一句副标题必须准确说明「多个入口、一条对话、可选运行位置」。
3. 中文和英文使用同一个品牌身份。若采用中英双名，两者应有自然关联，不再分别使用互不相关的产品名与工程代号。
4. 候选名要检查同类产品、仓库、域名和商标。初步网页搜索已发现 [Tern](https://tern.build/)、[Perch](https://perch.run/)、[Ferry](https://github.com/kzheart/ferry)、[Myna](https://myna.sh/features/agents)、[Swiftlet](https://www.swiftlet.ai/) 等名称存在相近的 AI 或 Agent 产品，不能直接采用；搜索结果也不能代替正式权利核查。

副标题的工作方向：**「多种入口，同一段对话。」 / “One conversation, across your channels.”** 名字不承担完整功能解释；副标题下再用网页与微信接续、本地 Agent 文字连接两个例子说明边界。

## 仓库与官网的整理方向

- README 开头：名字、一句准确的产品承诺、两个具体例子、真实工作区截图，然后是「适合谁」「现在能用什么」「如何开始」。详细技术状态和部署内容继续放在后半部分及文档中。
- 产品例子：在微信发消息，回网页接着聊；选择用户电脑上的 Codex，结果仍回到同一条主对话。第二个例子须明确标注当前仅有开发预览的文字接入。
- 用一张简单的结构图解释「渠道 → 账号与主对话 → 云端/本地 Agent → 原渠道回复」。图形只解释实际已实现的边界。
- 品牌图形应对应新名字，并同时适用于仓库头像、网站标记和浏览器图标。工作区布局、交互和现有玻璃视觉保持原样；品牌文案与素材可单独替换。

本次先统一 GitHub 仓库名称呈现、README 与仓库简介。应用内部标识、默认助手名字和线上地址属于单独的产品与迁移决策。
